= Type conversion between Kotlin and JavaScript

== Conversion of union types

=== TypeScript Declaration File
In the TypeScript declaration file the declared property type is:

[source]
----
number | Array<number> | null
----

However, this is not relevant for the tests further down. It is just a piece of code to satisfy the TypeScript compiler.
In plain JavaScript we could pass whatever we want.

=== Kotlin code
Kotlin code to determine the type:

[source]
----
  private fun printPropertyInfo(propertyName: String, property: Any?) {
    when (property) {
      undefined   -> println("$propertyName is undefined")
      null        -> println("$propertyName is null")
      is Double   -> println("$propertyName is a double value: $property")
      is Array<*> -> println("$propertyName is an array of length ${property.size}: $property")
      else        -> println("$propertyName has an unexpected type: $property")
    }
  }
----

CAUTION: The order matters! `undefined` and `null` seem to be the same.
If you check `undefined` first, "undefined" will be printed. If you check `null` first, "null" will be printed.

=== Consequences

It does not matter which type we declare in an external interface describing the MeisterCharts API.
On JavaScript side we can pass whichever value we want to the API (we can even pass a `String` to a property of type `Double?`).
An exception won't be thrown unless we make an unchecked cast.
